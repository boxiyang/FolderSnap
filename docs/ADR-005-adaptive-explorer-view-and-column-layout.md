# ADR-005: 资源管理器列表区自适应屏幕分辨率与智能列宽展开决策

## 状态
已通过 (Accepted) - 2026-09-16 经过用户针对性 Grill 对焦

## 决策背景与用户诉求
在 FolderSnap Desktop 运行与截图过程中：
1. 不同用户的显示器分辨率与 DPI 差异很大（1080P、2K、4K、轻薄本 1366x768 等）；
2. 资源管理器“详细信息”视图默认列宽较窄，长文件名常出现 `...` 截断，日期和大小可能被挤出可视区；
3. 用户要求：
   - 保持默认详细信息模式，但能根据屏幕分辨率和内容大小动态适配；
   - 关键列（名称、修改日期、大小）尽量完整展示；
   - **截图时，如果当前尺寸已经能完整呈现，则不需要强制全宽展开，避免无谓增加截图文件大小**。

## 决议方案 (Decisions)

### 1. 屏幕分辨率感知自适应 (Resolution-Aware Initial Geometry)
- 应用启动加载时，通过 `Screen.FromControl(this).WorkingArea` 读取当前主显示器工作区；
- 动态将窗体初始宽高设定为工作区的 **78% 宽 × 82% 高**（宽度区间约束在 [1180px, 1920px]，高度区间在 [720px, 1200px]），并自动屏幕水平垂直居中；
- 确保高分屏（2K/4K）与标准屏（1080P）均拥有充裕的物理像素直接铺展 4~5 个核心数据列。

### 2. 列表项内容大小动态适配 (Adaptive Column Auto-Fitting)
- 封装 `AutoFitColumns` 方法，通过向 `SysListView32` 控件发送 `LVM_SETCOLUMNWIDTH` 消息：
  - **列 0 (名称 Name)**：优先通过 `LVSCW_AUTOSIZE (-1)` 根据当前目录最长文件名自适应撑开（设定保底宽度 220px），杜绝长名称截断；
  - **列 1 (修改日期 Date Modified)**：保证不少于 140px，完整展示年月日与时间；
  - **列 2 (类型 Type)**：自适应或适度收缩（90~110px）；
  - **列 3 (大小 Size)**：保证不少于 85px，完整展示文件体积数值与单位；
- 触发时机：目录导航完成时（`FolderNavigated` 泵送延迟后）及窗口尺寸发生变化时自动执行。

### 3. 截图像素经济性与紧凑视口决策 (Smart Viewport & Compact Capture)
- 在截取图像前，通过 `Win32Native.GetScrollInfo(hWnd, SB_HORZ)` 检测当前 ListView 是否存在横向截断/滚动：
  - **若当前视口各关键列已能完整容纳（无横向溢出截断）**：
    保持当前自然尺寸直接截图，绝不强制折叠导航栏或过度拉伸，生成精简轻量、便于传输的紧凑截图；
  - **若检测到横向溢出或名称列严重挤压**：
    临时收起左侧导航栏自适应舒展为全宽视口，截取完成后毫秒级无缝恢复。

## 影响与收益
1. **开箱即最佳比例**：任何屏幕分辨率下启动，界面均大气舒展；
2. **长文件名零截断**：进入任何多层级、长命名的项目文件夹，文件名均完整显示；
3. **截图尺寸智能经济**：按需扩展，小目录截小图，长宽列截全图，文件体积最优化。
